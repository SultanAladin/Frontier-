Project-Drive cabin HMI — C++ port, proofs

Every sheet below is rasterised by the engine module Engine/SurfaceDisplay on the CPU and copied out through the versioned C interchange (ProjectDisplayInterchange). Nothing here is the HTML prototype. Sections 1–2 were captured from the real ProjectDrive code image while it drove the vehicle solver (_AgentScratch/seq.cpp harness; same path as DriveInterchangeChecks). Regenerate the static sheets with python Tools/Tests/CheckSurfaceDisplay.py.

1 · Live from the code image: cluster follows the solver (30 Hz cap)

Full throttle from rest, then reverse input to brake. Speed, rpm and gear come from VehicleTelemetry; the caption switches to LIVE VEHICLE once Play starts.

2 · Live from the code image: tablet, and a touch through the posed glass

A world ray from the driver's seat is handed to the DLL in FrontierProjectDisplayReading; the DLL resolves it against the tablet's pose (chassis transform × cabin mount), runs the Android/iPhone-style touch state machine, and the launcher icon under the finger opens. The status bar shows the live speed and gear.

3 · Where it sits in the real ControlVehicle (flat diagnostic projection)

The mesh has no HMI/steering sockets, so placement is estimated (DriveCabinLayout.h). Screens, bezels and the headliner lamp are authored onto the body span (materials 16–19, scene DriveCourse.r7) as emissive materials, so they are luminaires in the GI pass like the headlamps.
