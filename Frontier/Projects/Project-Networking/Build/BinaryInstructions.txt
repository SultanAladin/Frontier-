CHARGE / ONLINE ACCESS
======================
1. Extract this ZIP into a NEW folder (do not mix with earlier versions).
2. Install EpicOnlineServicesInstaller.exe once if needed. This is the official
   installer already in your EOS SDK Tools folder / shared Drive. Installation
   may ask for Windows permission; the app never runs it silently.
   https://drive.google.com/file/d/1JPhKa2DsiEQza6dFzyf48g5NAGPPYvUW/view
3. Open Charge.exe. This is Epic's configured, unmodified Bootstrapper, NOT the
   older direct NetworkingLogin.exe entry point. Keep its config alongside it.
4. Click Log in with Epic. The first time, Setup asks for the ROTATED application
   client secret (not your Epic password). Application IDs are prefilled.
5. Optionally enable Remember on this PC to store the client ID and secret in
   Windows Credential Manager for your Windows user. Otherwise they remain only
   in process memory, are wiped after submission, and must be re-entered.

Settings live under Setup. Advanced contains the Developer Auth Tool route,
permissions, SDK check, and Forget saved credential. To remove saved credentials
outside the app: Windows Credential Manager > Windows Credentials >
Frontier/Charge/Dev/EOSClient. Windows user credentials are not protection against
malware running as that user. No Epic player password or token is stored there.

Epic owns the Account Portal presentation. There is no invented browser OAuth
fallback, and no bypass of the service, app permissions, or Epic approval rules.
Status 1 means the application was not launched through the Bootstrapper;
status 2 means the EOS service is missing. Use Charge.exe, not App/*.exe.

The console colours informational, successful, warning and failed events.
SDK ready is NOT proof of login. Only successful EOS Auth AND Connect set the
verified state. Account permissions/consent and test-user eligibility still apply.

The runtime DLL is included. Do not copy files manually. This is a standalone
networking test project, not the complete Frontier engine. The project DLL stays
under Build/Output. CI checks rendering, SDK lifetime and extracted-package
startup; it does NOT claim a real account login, overlay, or service-start test.
